# 学习路线

## 先用起来

用示例复习五张卡，再写自己课程的五张卡。先回答再翻面，真实评分。第二天再回来，不追求第一次就全会。

## 看懂调度

读 `src/scheduler.mjs`，手算同一张卡连续三次“正常”、一次“重来”后的状态。给定固定时间 `now=0`，解释下次到期时间为何可以确定性测试。思考固定天数与本地日历日的区别。

## 看懂可靠写入

读 `src/store.mjs` 的 `review`：先检查幂等事件，再读取卡片版本，计算下一状态，最后在事务中同时更新两张表。用同一个 `eventId` 提交两次，确认只记录一次。用旧版本配新事件提交，确认报错。

## 模型输出如何变成数据

读 `src/cards.mjs`：模型返回的行号、原文子串、类型均需要校验。构造答案不存在、行号越界、空题目的响应。思考答案在原文中为什么仍不足以保证问答正确。

## 有意义的扩展

1. 增加标签与按课程筛选，保持旧命令兼容。
2. 实现卡片归档和显式内容更新，讨论更新答案是否应重置进度。
3. 给调度事件增加复习耗时，在导出数据上计算到期率、失败率。
4. 为 schema 增加真正的版本迁移，测试从旧数据库升级并备份。
5. 比较简单固定间隔、当前算法与更复杂算法，避免在没有数据时宣称提升记忆效果。

面试可解释的问题：幂等和版本检查分别解决什么？为什么把事件日志和卡片更新放进一个事务？发生崩溃时如何保证两张表一致？
